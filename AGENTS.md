# PseudoPy agent notes

## Skills
- For application/compiler fixes and regression verification, load `pseudopy-change-verification` from `.opencode/skills/pseudopy-change-verification/SKILL.md`.
- Project skills live at `.opencode/skills/<name>/SKILL.md`; include YAML `name` (matching the folder) and a `description` specifying when to use the skill.
- Verify discovery with `opencode debug skill --pure`. Imported skills may reference absent Claude Code agents/commands; check availability before following those steps. The imported `skill-tester` validates a different schema, not OpenCode compatibility.

## Source boundaries
- `app.js`, `compiler.js`, `database.js`, and `devtools.js` are checked-in generated outputs. Edit sources listed in `src/bundles.json`, then run `npm run build`; include regenerated outputs with source changes.
- Browser modules are ordered classic scripts sharing lexical state and HTML handlers, not ES modules. The bundler concatenates files in manifest order; preserve that order and register new modules there.
- Root `mapper.js`, `metrics.js`, `pwa-updates.js`, `ui-icons.js`, and `sw.js` are maintained directly, not generated by that bundler.
- `server.js` starts Express using `server/create-app.js`; `api/` contains Vercel handlers. Both backend paths share `server/collection-store.js` through `api/_db.js`. This in-memory backend is distinct from the browser Firestore/IndexedDB layer in `src/database/`.
- `scripts/build.js` injects `package.json`'s version into `src/app/app-version.js`'s placeholder when building `app.js`. The displayed app version and service-worker cache names are separate mechanisms.

## Commands and prerequisites
- Use Node 22 to match CI and Python 3 for compiler execution tests. Install with `npm ci`; after source edits run `npm run build`, then `npm test`.
- `npm test` first checks bundle freshness, then runs `node --test tests/*.test.js`, then `node test_operator_translation.js`. The last command does not run if the Node suite fails.
- Focused example: `node --test tests/semantic-types.test.js`. Focused tests bypass the npm freshness check; rebuild first when testing bundled code.
- Additional instructor/data compatibility checks: `node verify_app_refactor.js` (outside the npm test glob).
- Compiler tests invoke `process.env.PYTHON || 'python3'`. On Windows, set `$env:PYTHON` to a working Python executable if needed; a Windows Store alias is not a working interpreter. Missing Python is a prerequisite failure, not a passing suite.
- `npm start` / `npm run dev` build first and serve on port 3000 (or `PORT`); neither command provides a watch build.

## Runtime constraints
- For precached asset changes, bump `CACHE_NAME` and `VENDOR_CACHE_NAME` in `sw.js`; inspect its asset arrays rather than assuming which bundles are cached. Keep vendor loader URLs aligned with cache URLs.
- Python executes in vendored Skulpt in the browser, while compiler comparison tests use CPython. Configure `execLimit` before `Sk.importMainWithBody`; do not rely on `Sk.misceval.timeout` in this vendored build.
- Browser `dbAdd`/`dbSet`/`dbUpdate` save locally before attempting Firestore. Unconfirmed cloud writes reject with `error.localOnly === true`; offline/transient writes are queued, permanent refusals are not. Preserve the local draft when handling rejection; see `tests/cloud-save-failure.test.js`.
- Firebase configuration comes from `src/database/firebase.js`, with a `window.__FIREBASE_CONFIG__` override when it supplies `projectId`. Check the resolved configuration rather than inferring the cloud project from old docs or seed utilities.
- Language semantics: `docs/compiler-language.md`. Offline persistence/queue behavior: `docs/OFFLINE.md`. Architecture background: `docs/architecture.md`; prefer current scripts and manifests when prose disagrees.
